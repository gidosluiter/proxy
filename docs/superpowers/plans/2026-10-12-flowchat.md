# FlowChat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working, free GPT-style chat website and publish the tested project on GitHub.

**Architecture:** React chat state is isolated from a worker-based browser inference engine. Qwen2.5-0.5B-Instruct runs with Transformers.js q4 WASM. Preserve the existing proxy as a legacy entry and keep Node and Pages builds functional.

**Tech Stack:** Node 24, React, TypeScript, Vite, Transformers.js 3.8.1, React Markdown, remark-gfm, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-flowchat-design.md`

## Global Constraints

- Free open-source dependencies; no accounts, API keys, paid service or fake replies.
- Dutch UI; describe the engine as an open model, not an OpenAI GPT model.
- Single-threaded WASM in a dedicated worker; serve runtime files from the project path.
- Preserve working legacy proxy/API and project-relative assets/hash routing.
- Test real inference separately from deterministic UI fixtures. Verify actual live deployment before claiming publication.

## Review Focus

- Stop during download/prefill and late messages after changing chat must not corrupt history.
- Invalid/quota-limited local storage must not crash the application or overwrite valid data silently.
- Markdown HTML and unsafe URLs must not execute.
- Long histories must stay bounded and keep a valid alternating model context.
- Worker/WASM URLs must resolve on `/proxy/` and Node CSP must permit real inference.
